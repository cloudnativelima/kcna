# Labels

Un label es una “etiqueta” que le pones a un recurso:

```yaml
labels:
  app: frontend
  env: production
  tier: web
```

**¿A qué objetos se les pueden poner labels?** Prácticamente a todo:

- Pods
- Deployments
- Services
- Nodes
- Namespaces

## ¿Para qué sirven?

1. Seleccionar recursos (lo más importante)

Los labels permiten que otros recursos encuentren a quién deben apuntar.

Ejemplo: un Service usa labels para saber qué Pods atender:

```yaml
selector:
  app: frontend
```

2. Organización lógica

Puedes agrupar recursos por:

- Ambiente: dev, staging, prod
- Aplicación: frontend, backend
- Equipo: team-a, team-b

3. Automatización y gobernanza

Herramientas como:

- Kubernetes
- Helm
- ArgoCD

usan labels para:

- Aplicar políticas
- Hacer despliegues
- Filtrar recursos

4. Filtrado con kubectl

```yaml
kubectl get pods -l app=frontend
```

Solo muestra pods con ese label.
